# PR 53: 启用 TCP Keepalive、加速心跳判定、重置重连避退与日志本地化时间

## PR摘要
通过 `socket2` 在 WuKongIM WebSocket 建立前手动配置并启用 TCP Keepalive，以及大幅缩短心跳发送间隔与超时时间，**核心解决 macOS 系统休眠唤醒后，小助手需要长达 2 分钟左右才能建立重连（因 WebSocket 协议层无法自动感知物理连接断开，极度依赖长时间的应用层心跳超时感知）的重连延迟问题**；同时优化了通道重连的指数避退重置逻辑以缩短偶发断线二次等待，并将系统日志时间格式化为本地时区时间。

## 背景
1. **macOS 休眠唤醒后建立重连延迟过长**：
   PR 52 虽解决了休眠唤醒后的重连可行性问题，但在实际使用中，macOS 唤醒后小助手仍需耗时长达 2 分钟左右才能完成重连建立。这是因为底层的 WebSocket / TCP 物理链路在断网或切网时无法立刻感知连接已被关闭，主要依赖被动的应用层心跳超时来确认连接死亡。
2. **缺乏 TCP 探针与保活时效性低**：
   原有的套接字没有配置 TCP Keepalive，无法通过系统协议栈定时发送 TCP 探针来强行终结处于半开状态的僵尸连接。加上原先 60 秒级的心跳超时判定，导致感知物理断开并启动重连的过程极其漫长。
3. **退避惩罚残留导致恢复滞后**：
   通道 Listener 的自动重启和重连应用了指数避退算法。然而，如果因单次偶然偶发故障导致避退重连时间累加得极大，在故障恢复且成功连接后，一旦再次发生偶发断开，退避计数并不会立刻归零，导致重连依然需要等待非常冗长的避退时间。
4. **UTC 日志不便于运维排查**：
   日志中的时间戳默认为 UTC 零时区，在中文或本地运维团队排查生产问题时需要手动换算，极易造成时间轴对齐偏差。

## 方案
1. **手控 TCP 套接字并启用 TCP Keepalive**：
   - 引入 `socket2` 库。
   - 解析 WuKongIM 的 WS 链接地址，获取主机名和端口并进行异步 DNS 解析。
   - 使用 `socket2::Socket` 手动创建流式套接字，开启 `set_keepalive(true)` 且利用 `socket2::TcpKeepalive` 进行配置：探测前等待时长 `time` 为 10 秒，探测间隔 `interval` 为 5 秒。
   - 设置非阻塞后，转换为 `tokio::net::TcpStream` 交付给 `tokio_tungstenite` 执行后续的 client 异步握手。
   - **效果**：即使 macOS 上 TCP 状态由于网络切换或唤醒而维持在 ESTABLISHED，一旦 10 秒无数据且探测包发送失败，操作系统也会在 15s 内快速强拆该 zombie 连接，缩短感知物理断开的时间。
2. **极速化应用层心跳保活参数**：
   - 将发送 Ping 的间隔时间 `PING_INTERVAL` 从 30 秒下调至 10 秒。
   - 将应用层心跳超时时间 `HEARTBEAT_TIMEOUT` 从 60 秒大幅下调至 25 秒。
   - **效果**：双重保障下，客户端最快可在 25 秒内感知到链路挂死并进行重建，从而使小助手的重连建立时间从 2 分钟级别压缩至 25 秒以内。
3. **成功连接重置避退（Backoff Reset）**：
   在 `zeroclaw-channels` 编排器的 supervised listener 循环里，跟踪 Listener 成功运行的时长。若稳定运行达 30 秒以上，则认为连接已步入健康稳定状态，此时将 `backoff` 重置回 `initial_backoff_secs`（即 1 秒），避免残留之前累加的过长重连时延惩罚。
4. **日志本地化时间戳**：
   在 `src/main.rs` 中实现 `LocalTimer`（实现 `tracing_subscriber::fmt::time::FormatTime`），以 `chrono::Local` 输出本地时区的微秒级精确时间（`%Y-%m-%dT%H:%M:%S%.6f%:z`），并全局配置到所有 log 打印 layer 中。

## 配置（Optional)
- 心跳发送周期 `PING_INTERVAL` 设定为 `10s`。
- 心跳超时限制 `HEARTBEAT_TIMEOUT` 设定为 `25s`。
- 稳定连接判定时间阈值设定为 `30s`，稳定后重置 backoff 计数。

## 实现要点
- 使用 `socket2` 来定制套接字参数，将其适配成 `tokio::net::TcpStream` 再由 `tokio_tungstenite` 托管。
- 通道监听器状态机中成功连接后的避退计时重置逻辑。
- 自定义 `FormatTime` 适配器集成至 `tracing-subscriber`。

## 测试方案
1. **TCP 探针分析**：
   使用网络抓包工具（如 tcpdump）监听对应端口，确保连接闲置 10 秒后，会有底层的 TCP Keep-Alive 探测包周期性发出。
2. **极端超时与极速重连验证**：
   突然封禁网络端口，确认连接必在 25 秒内强行拆断，并立即（1 秒延迟）发起第一次重连尝试。
3. **退避重置策略观察**：
   断网引起连接避退时延提升（如累加到 16 秒），重连成功并正常接收数据达 30 秒以上，再次阻断，检查重连是否是在 1 秒（首选退避时延）后直接发起。
4. **日志时间戳比对**：
   检查控制台和输出的 JSONL 日志，验证时间戳格式是否已变成带本地时区偏移的精准时间戳（如 `+08:00`）。
