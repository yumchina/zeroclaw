## 1. 目标

完整闭合上游 PR 在 cancel-on-fanout 路径上留下的 3 个正确性问题（I1/I2/I5），同步把同样问题的 lark channel 一起补好，让多 superuser fan-out 场景下的非 winner 卡片能在用户屏幕上**显式更新**为「此请求已被处理 — 同意/拒绝/始终允许」，且本地化跟随 ZeroClaw 全局 locale。

非目标：

- 不引入新的 channel 类型
- 不改 grant store / audit log
- 不重新评估 fan_out 的并发模型（仍是 `JoinSet` 同步 await）
- 不显示 decider 的名字（master_id 仅入 audit log）

## 2. 关键决定（brainstorming 锁定）

| # | 决定 | 否决项 |
|---|---|---|
| 1 | 走 spec §4.1「方向 A」：`ChannelApprovalRequest` 新增 `approval_id: Option<String>`，broker 生成、channel 优先复用 | B（broker 维护回调映射）/ C（完全 channel-side） |
| 2 | 本 PR 范围 = broker + dawn_im + lark | 仅 dawn_im / 全部 channel 扫一遍 |
| 3 | dawn_im cancel UX = 发新 `INTERACTIVE_CARD`（dawn_im 协议无 patch 能力） | 纯文本 / 混合 fallback |
| 4 | trait `cancel_approval(approval_id, recipient, reason)`；broker 走 fluent i18n 拼 reason，channel 不感知 locale。**注**：brainstorming 第 4 问最初选「保留原 `(id, reason)` 签名」；§5 数据流推演发现 channel 端 pending key 需精确到 `(approval_id, recipient)` 才能避免同 channel 多 recipient 的 HashMap 覆盖，因此最终签名扩展为 3 参 | 引入 CancelReason struct / channel 内部 O(N) 扫描 / 改 request_approval 返回 CancelHandle |
| 5 | 卡片不显示 decider 名字，只显示决定状态；master_id 仅入 audit log | 显示 master_id / 走 IdentityResolver 查 display name |

## 3. 架构

```
┌─────────────────────────────────────────────────────────────────┐
│ ApprovalBroker (runtime)                                        │
│  - 生成 canonical approval_id (Uuid v4)                         │
│  - 填进 ChannelApprovalRequest.approval_id                      │
│  - fan_out 跟踪 (channel_ref, recipient, channel) 三元组         │
│  - winner 选出后,对 (chref, recipient) != winner 调 cancel       │
│  - cancel reason 走 i18n::get_event_string_with_args(...)        │
│  - identify_decider 算 master_id,仅用于 audit log               │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ↓ Channel trait
┌─────────────────────────────────────────────────────────────────┐
│ ChannelApprovalRequest { approval_id: Option<String>, ... }     │
│ async fn cancel_approval(approval_id, recipient, reason)        │
└─────────────────────────────────────────────────────────────────┘
                              │
       ┌──────────────────────┼──────────────────────┐
       ↓                      ↓                      ↓
┌─────────────┐      ┌──────────────────┐   ┌──────────────────┐
│ DawnIM      │      │ Lark             │   │ 其他 channel     │
│             │      │                  │   │ (trait 默认 Ok) │
│ pending key │      │ pending key      │   │                  │
│ = (id,      │      │ = (id,           │   │                  │
│   recipient)│      │    open_id)      │   │                  │
│             │      │                  │   │                  │
│ cancel:     │      │ cancel:          │   │                  │
│ send 新卡   │      │ patch 原卡       │   │                  │
│ (RPC send,  │      │ (用 message_id   │   │                  │
│  无 patch)  │      │  + 已有 patch)   │   │                  │
└─────────────┘      └──────────────────┘   └──────────────────┘
```

dawn_im 与 lark 各自匹配协议能力（dawn_im 只能 send 新卡，lark 有 patch），但对 broker 透明 —— broker 只关心 `cancel_approval(...) -> Result<()>`。

        &self,

`cancel_approval` 真发卡：

```rust
async fn cancel_approval(
    &self,
    approval_id: &str,
    recipient: &str,
    reason: &str,
) -> anyhow::Result<()> {
    let removed = self.pending_approvals.write().await
        .remove(&(approval_id.to_string(), recipient.to_string()));
    let Some(pending) = removed else {
        // 已超时或已被点击,无补卡价值
        return Ok(());
    };
    let card = build_resolved_card(approval_id, reason);
    let payload_b64 = base64::engine::general_purpose::STANDARD
        .encode(serde_json::to_string(&card)?);
    let (channel_id, channel_type) = parse_recipient(recipient);
    let topic_out = pending.topic.clone();
    let setting_out = topic_out.as_ref().map(|_| 8u32);
    let params = SendParams {
        from_uid: Some(self.uid.clone()),
        client_msg_no: Uuid::new_v4().to_string(),
        channel_id,
        channel_type,
        payload: serde_json::Value::String(payload_b64),
        header: None,
        setting: setting_out,    // 复用 request_approval 的 topic flag
        msg_key: None,
        expire: None,
        stream_no: None,
        topic: topic_out,    // cancel 卡落在原审批所在 topic 线程
    };
    let _: serde_json::Value = self.send_rpc("send", params).await?;
    Ok(())
}
```

> cancel 卡的 `topic + setting` 复用原 `request_approval` 时保存在 `PendingApproval.topic` 的值，确保用户在原 topic 视图就能看到「已处理」更新（符合 spec §3 用户视角的「自己的卡片自动更新」预期）。

```rust
async fn cancel_approval(
    &self,
    approval_id: &str,
    recipient: &str,
    reason: &str,
) -> anyhow::Result<()> {
    let removed = self.pending_approvals.lock().await
        .remove(&(approval_id.to_string(), recipient.to_string()));
    let Some(pending) = removed else { return Ok(()); };
    if pending.message_id.is_empty() {
        // 当初 send 时没拿到 message_id,patch 无效
        return Ok(());
    }
    self.patch_resolved_card_with_reason(
        &pending.message_id,
        &pending.tool_name,
        &pending.arguments_summary,
        reason,
    ).await?;
    Ok(())
}
```

## 5. 数据流（race-free）

```
[u_alice 在 dawn_im 触发 shell]
  ↓
ApprovalBroker::request_decision
  ↓
approval_id = "uuid-CANONICAL"
request = ChannelApprovalRequest { approval_id: Some("uuid-CANONICAL"), ... }
  ↓
fan_out([("dawnim.work", "u_admin1"), ("dawnim.work", "u_admin2")], ...)
  ↓
spawn task A: request_approval("u_admin1", request)
  → pending[("uuid-CANONICAL", "u_admin1")] = sender_A
  → send_rpc 给 u_admin1 推卡
spawn task B: request_approval("u_admin2", request)
  → pending[("uuid-CANONICAL", "u_admin2")] = sender_B
  → send_rpc 给 u_admin2 推卡

[u_admin2 点击同意]
  inbound: WkApprovalAction { approval_id: "uuid-CANONICAL", action: "approve" }
           RecvNotificationParams { from_uid: "u_admin2", ... }
  ↓
pending.remove(("uuid-CANONICAL", "u_admin2")) → sender_B
sender_B.send(Approve) → task B 返回 Some(Approve)

broker fan_out:
  winner = (Approve, "dawnim.work", "u_admin2")
  reason = compute_cancel_reason(Approve)
         = i18n.get("event-approval-cancelled-status",
                    decision = i18n.get("event-approval-decision-approve"))
         = "此请求已被处理 — 同意" (zh-CN)

  for (chref, recipient, ch) in alive_targets:
    if (chref, recipient) != ("dawnim.work", "u_admin2"):
      ch.cancel_approval("uuid-CANONICAL", "u_admin1", &reason)
  ↓
DawnIM::cancel_approval("uuid-CANONICAL", "u_admin1", "此请求已被处理 — 同意"):
  pending.remove(("uuid-CANONICAL", "u_admin1")) → Some(sender_A) [drop]
  build_resolved_card("uuid-CANONICAL", reason) → INTERACTIVE_CARD
  send_rpc("send", SendParams { channel_id: "u_admin1", channel_type: 1, ... })
  ↓
u_admin1 屏幕上新出现「此请求已被处理 — 同意」卡片
```

## 6. 错误处理

| 错误 | 处理 |
|---|---|
| broker 调 `cancel_approval` 失败 | log WARN，不阻塞 broker return；用户体验降级（loser 卡片仍可见）但功能正确 |
| broker `compute_cancel_reason` 拿到 missing fluent key | i18n 现有约定返回 `{key}` 标记，channel 仍可塞进卡片 body；视为维护信号 |
| channel cancel 收到的 `(approval_id, recipient)` 未命中 pending | 静默 return Ok（已超时 / 已被用户点击 / broker 重复 cancel）；**不**发卡 |
| dawn_im `send_rpc` 失败 | 返回 Err 让 broker log warn；**不**入 `pending_outbound` buffer（cancel 卡是 UX 提示，过期补发反而误导） |
| lark patch endpoint 失败 | 返回 Err 让 broker log warn；同 dawn_im 不入 retry queue |
| race：cancel 与 inbound 同时 `pending.write()` | RwLock 序列化，先拿到锁的赢；`JoinSet::shutdown()` 丢弃 loser task 的返回值 —— 无副作用，仅 UI 短暂双卡可能（罕见、不修） |

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **DawnIM `recipient` 字符串与 inbound `from_uid` 格式不一致** | pending key 永远查不到，所有审批超时 | 实施时校验 `parse_recipient` 与 inbound `from_uid` 的关系；若发现差异，在 channel 内 normalize 后再作 key.1（不影响 broker 端 trait） |
| **superusers 配置里的 master_id 与 dawn_im local uid 不一致** | broker fallback 路径传的 recipient channel 找不到 | 在 spec 6 节确认假设；实施时若发现，加 normalize 层或在 reverse_lookup fallback 路径上 normalize |
| **lark `operator_open_id` 与 broker resolve 出的 recipient 字符串不一致** | 同上 lark 侧 | 实施时校验 IdentityResolver 在 lark 上 reverse_lookup 返回的是不是 open_id |
| **trait 签名扩展破坏未在 tree 内的 channel 实现** | 编译错 | 默认 impl `Ok(())`，未实现 cancel 的 channel 不受影响 |
| **fluent key 漏写另一语言** | 用户看到 `{key}` 标记 | 7.4 的 `approval_decision_keys_present_in_both_locales` 测试守住 |
